# HNI Stage 08 — Research and feature audit

## Implemented source
- `src/services/graph-core.ts` implements typed adjacency, invalid endpoint and duplicate ID checks, filtered neighbors, 18-node bounded one/two-hop traversal, radial positions, lexical indexing/ranking and shared IDs. `discovery-adapter.ts` projects the canonical dataset; `discovery-index.ts` creates one shared runtime index. The offline Node tests execute these same pure functions against the real dataset; no parallel graph JSON exists.
- 146 nodes: 18 laws, 54 concepts, 18 cases, 38 claims, 6 findings, 12 sources. 127 immutable editorial edges, 189 derived catalog associations = 316 indexed links. Derived `link:` keys are transient, not new canonical EDG IDs. `attributed_claim` is the existing law association; `assessed_by` is the existing finding link; `cites` is a deduplicated source association resolved through REF.sourceId. These catalog links are intentionally outside the research relationship enum and are never represented as new empirical evidence.
- Network route now renders interactive SVG, directional arrows, solid editorial edges and dashed catalog links, node and edge selection, neighborhood expansion/collapse, filter combinations, native keyboard-accessible buttons, edge explanation and source panels, zoom/fit and directional pan controls. Native list uses the identical bounded subset; an explicit all-relationships list exposes all filtered connections. Node labels are abbreviated in SVG; full titles and 44px native buttons appear in the list. Focus, depth, selection, query, type, relation, editorial filter, mode and camera parameters live in the HashRouter query. User can return using browser history or detail-page Explore network links (those backlinks start a new focus, not exact previous camera restoration). No drag/pinch gestures or animation engine claimed.
- Search now covers all 6 record types, including case people, chronology, claim qualifications, findings and author/journal/DOI metadata. All terms must match; exact titles/IDs receive higher rank. Filters combine type, law and claim-level evidence, including blank-query filtered browsing. Source records have no scientific evidence status by design. Search snippets are literal excerpts of the indexed original editorial data. Lexical only; no semantic AI. Common curly/straight apostrophes normalized.
- `#/compare` lets readers select two laws or two concepts, with central arguments/definitions, mechanisms, distinctions, alternatives, individual claim statuses, sources, exact shared case IDs for laws and actual direct editorial edges. Existing four curated concept pairs retain their original view `#/atlas/compare`. Missing pair-specific editorial text is explicitly labeled; no runtime synthesis.
- Command Center now derives discovery links from actual edges and finding associations, with explanations. Historical verification and evidence-coverage captions corrected. Detail routes for law, concept, case, claim, finding and source have network links; finding entity routing is corrected to `/evidence/findings/:id` and source pages list linked findings. Existing all-law synthesis lanes remain. No new permanent modules.

## Research preservation
All original `src/data/` and `research/` files byte-identical to Stage 07. All 127 editorial relationships have nonempty explanations and reference IDs, no duplicate directed relation/endpoints, no reverse duplicates of the same relation, valid endpoint types and source references. The original edge wording may predate Stage 07 corroboration; edge detail directs readers to current records. 7 editorial relationship types currently used; unused types remain valid schema options. No new evidence claims, no independent source review, no section coverage upgrades. 18 chapters remain partially reviewed; 23/60 substantive sections, 37 remaining. Six limited/mixed findings and five narrowly corroborated cases remain at Stage 07 scope. 8 of 14 evidence backlog items remain untouched. No new history or psychology sourced in this UI stage.

## Known limitations
No real production bundle, browser, iPhone Safari or assistive technology test. Graph layout is deterministic radial rather than a force simulation; dense overlapping links and small visual labels may require the accessible list. The cap can omit links; count is shown. Full-corpus list can be long (316 links). Selection/back/forward, zoom/pan controls and actual mobile rendering require browser smoke testing. No performance claims about compiled bundle size or device responsiveness. Stage 09 must address actual npm/CI gate and avoid mistaking offline tests for browser certification.
