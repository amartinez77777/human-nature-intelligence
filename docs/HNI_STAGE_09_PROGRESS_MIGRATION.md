# Stage 09 progress and migration contract

## Dataset vs. user state
Canonical dataset schema advances from 2 to 3; exercise types and lesson records extend the domain model. Migration is recorded in research/ID_ALIASES.json; no aliases or reassigned IDs. All 47 original exercise IDs and correct choice IDs remain unchanged. PATH-0001 identity and prior membership are preserved. Scenario envelope remains v1, and all six scenario records and scenario-engine code remain unchanged.

User progress remains schema v2 with an **optional additive `academyAttempts` field**. Storage key remains `hni.user-progress.v1`. Valid original v1 payloads initialize an empty `scenarioProgress`; valid Stage 09A v2 payloads retain scenario histories and all original fields. No write occurs during initial load/migration. New Academy saves add a map keyed by EXR ID; each value contains `exerciseId`, `revision` and `choiceIds`. Only the latest submitted attempt per exercise is recorded, not every attempt or a score. Lesson completion is derived from saved supported exercise IDs; the provider also sets the existing path boolean when its ordered lessons are complete. An inherited true path flag is preserved as historical completion, not proof of completion of the expanded curriculum. The 18 revised prompts retain historical completion and explicitly mark revision 2.

`recordAcademyAttempt` performs an immutable merge; `ProgressContext` commits only after successful validated storage write. Unsupported choice IDs, duplicate choices, invalid revisions, unknown EXR/PATH IDs and invalid scenario histories reject the backup. Old duplicate completion/bookmark IDs retain inherited normalization semantics. Original corrupt storage is not automatically overwritten. The import UI shows Academy and simulation counts and requires affirmative replacement; cancel and storage failure preserve the old value.

The same JSON export envelope continues to work, and both education systems survive round trips. The updated app imports supported v1 and v2 data. Do not downgrade to Stage 09A for writing a newer backup: its older v2 parser does not know the optional Academy field and may omit it when exporting. Save a separate backup before downgrading. Future schema changes should explicitly version and migrate unsupported fields. No cloud sync, mandatory account, or runtime AI.
